# 验证说明

## 自动检查

```powershell
npm test
```

Node.js 内置测试运行器覆盖项目恢复、文件边界、原始附件上传、HTTP 会话与同源检查、MCP、任务依赖、发送状态机、暂停保护、会商门控、官方协议模拟、统筹进程隔离、错误分类及 Windows 文件锁重试。

自动检查不登录官方客户端、不启动真实 AI 推理，也不读取已有工作台的 .data/。测试使用系统临时目录和模拟接口。少量测试启动临时本地 HTTP/MCP 子进程，结束后关闭。

2026-10-20 的本机自动检查为96项通过。源码发布时会重新运行，具体数量以当前输出为准。GitHub Actions 提供 Windows 自动检查和原生编译；尚未声称远程 CI 已成功运行。

## Windows 原生手动检查

```powershell
npm run build:native
node scripts/verify-native.mjs
node scripts/verify-pipeline.mjs
```

这些命令启动本项目的验证窗口，检查独立桌面、后台控件操作、截图和文件。验证窗口明确标记为非 AI。结果写入 artifacts/，不进入源码发布包。

## 真实客户端状态

- 曾使用官方 Codex 本地协议创建真实统筹会话，并取得结构化规划和不同角色的评议提示词。
- 曾在特定 Windows 环境验证 TRAE 生成/修正小游戏、豆包本地检验，以及豆包工作读写原始附件和交付图片。
- 新版三方独立会话的完整自动会商仍未验收。TRAE 专用实例登录按钮无反应是当前已知阻塞。
- 旧版真实验证不能证明新版本客户端继续兼容，原生测试窗口通过也不证明第三方 AI 窗口通过。

涉及实际模型的 verify-codex-runtime.mjs、verify-council-planner.mjs 和官方客户端实验脚本为可选手动实验，可能使用账户额度、创建真实对话或发送任务。它们不会由 npm test、CI 或源码打包自动运行。操作前请阅读脚本，只选择自己专用且空闲的会话。

公开源码不附带私人项目记录、真实聊天截图、会话 ID、登录资料或历史运行日志。
