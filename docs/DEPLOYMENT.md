# Windows 本地部署教程

这份教程面向第一次运行项目的用户。当前版本部署在自己的 Windows 电脑上：浏览器显示工作台，本地 Node.js 服务管理项目，Windows 组件操作这台电脑中的官方 AI 客户端。GitHub 用于存放源码和分发下载。

> 这是未完成的实验原型。可以先验证工作台启动，再逐个接入客户端。TRAE 独立桌面登录和完整三方自动会商仍有未解决项，不保证下载后所有客户端都能自动跑通。

## 1. 准备环境

| 环境 | 用途 |
| --- | --- |
| Windows x64 电脑，建议 Windows 10/11 | 编译并运行原生组件 |
| Node.js 22 或更新版本 | 运行本地服务与自动检查 |
| Windows .NET Framework 4.x 编译器 | 首次生成原生操作组件 |
| 可用且已登录的官方 Codex 运行时 | 自动统筹，需要时才使用 |
| 自己选择的 TRAE、豆包、豆包工作等官方桌面客户端 | 实际执行，需要逐个配置和验证 |

先安装 [Node.js 官方下载页](https://nodejs.org/en/download) 提供的 Windows x64 安装程序，选择符合 Node.js 22+ 要求的 LTS 版本。安装后重新打开 PowerShell，执行：

```powershell
node --version
npm.cmd --version
```

能显示版本号即可。若提示找不到命令，确认已安装 Node.js 并重新打开终端。

原生构建脚本会查找 Windows 下的 `.NET Framework64\v4.0.30319\csc.exe`。如果提示缺少编译器，请先补齐 Windows 对应的 .NET Framework 组件；单独安装新版 .NET SDK 不一定提供这个路径。

## 2. 下载源码

1. 打开 [MOO8888/agent-dock](https://github.com/MOO8888/agent-dock)。
2. 点击绿色 **Code → Download ZIP**。
3. 解压到自己可写的目录，例如 `D:\Projects\agent-dock`。
4. 确认该目录中能看到 `package.json`、`start.cmd`、`src`、`web`、`native`。

请先解压，不要直接在 ZIP 预览窗口中启动。以下命令都在包含 `package.json` 的这一层目录执行。

## 3. 第一次启动：建议使用终端

在源码目录的地址栏输入 `powershell` 并回车，或在终端进入你自己的目录：

```powershell
cd D:\Projects\agent-dock
npm.cmd run build:native
npm.cmd start
```

路径请替换成实际解压位置。项目没有 npm 运行依赖，当前不需要先运行 `npm install`。

构建成功后，`native/bin/` 会出现本地生成的程序。服务启动成功会打印：

```text
AgentDock 已启动：http://127.0.0.1:4318
```

在浏览器打开 [http://127.0.0.1:4318/](http://127.0.0.1:4318/)。第一次运行时，项目列表为空，默认成员包含 Codex、TRAE、豆包和豆包工作。

终端启动方式需要保持该终端运行；按 `Ctrl+C` 可以停止服务。页面能打开只代表工作台已启动，还没有证明官方 AI 已接入或任务已执行。

## 4. 日常启动：双击 start.cmd

首次构建成功后，通常可以双击源码根目录的 `start.cmd`。它会检查、按需构建组件，通过当前 Windows 桌面启动后台服务，再打开浏览器。

- 该方式不需要一直开着启动终端。
- 关闭网页不会停止后台服务。
- 电脑关机、重启或服务进程退出后，需再次启动。
- 当前没有安装开机自启动或常驻守护服务。
- 若启动失败，先用上一步的终端方式查看错误，再查看 `.data/server-error.log`。

如果需要排查或结束后台实例，可以在本地 `.data/run.json` 查看本项目记录的 PID，并在任务管理器核对该进程。不要按名称批量结束所有 Node.js 进程。熟悉终端前，推荐用终端启动方式管理启停。

## 5. 准备 Codex 统筹

安装并登录官方 Codex 客户端/运行时，参考 [OpenAI 官方入门说明](https://learn.chatgpt.com/docs/quickstart?setup=app)。本项目自动统筹使用官方本地 App Server，要求该运行时采用 ChatGPT 登录，不提供 API Key 回退。

如果你的原生 Codex 命令已经可用，可以检查登录方式：

```powershell
codex login status
```

没有登录时，使用官方登录界面，或按 [官方认证说明](https://learn.chatgpt.com/docs/auth) 执行 `codex login` 并自行完成浏览器登录。仅在网页上登录 ChatGPT，不足以证明本地运行时已经登录。

回到共作，点击右上角 **Codex 待命 / 自动统筹 → 检查统筹连接**。检查通过后显示 **Codex 已就绪**。此检查只确认官方协议和登录，不创建模型任务、不绑定执行成员。

### 找不到 Codex 运行时怎么办

原型会查找 `%LOCALAPPDATA%\OpenAI\Codex\bin` 下的原生 `codex.exe`，也支持环境变量 `AGENT_DOCK_CODEX`。不同客户端发行方式、安装路径和版本可能不兼容自动查找。

如果你已经确认官方原生可执行文件的实际位置，可以在同一个 PowerShell 窗口中指定它，再启动共作：

```powershell
$env:AGENT_DOCK_CODEX = 'C:\Tools\Codex\codex.exe'
npm.cmd start
```

上面只是示例路径，必须替换为自己的真实文件。变量应指向原生 `.exe`；某些安装方式提供的 `codex.cmd` 包装脚本尚未保证能被当前启动器直接识别。这里使用终端启动，方便确认环境变量和错误。

可用模型和推理等级以官方运行时与账户为准。点击群聊输入区下方的 Codex 设置按钮可以读取官方选项；完成实际轮次后才会记录已应用。

## 6. 准备和绑定执行成员

建议先接入一个自己确认可用的成员，成功后再逐个增加。

1. 自行安装需要的官方桌面客户端，确认在正常桌面能打开、登录并使用。
2. 打开共作左侧 **团队 → 设置**，填写该客户端的完整 `.exe` 路径。
3. 按需要开启“运行当前项目时自动绑定”。需要自动派发时，使用共作独立工作桌面，并按设置开启专用客户端启动。
4. 客户端启动参数和专用配置目录依客户端而异。不要照抄另一台电脑的路径，也不要把已有认证目录复制给别人。
5. 专用实例首次登录、验证码、文件夹信任和权限确认，由用户自己在官方界面完成。
6. 若需要人工处理，点击右侧 **进入工作桌面**，处理后点击左上角 **返回我的桌面**。
7. 返回后项目保持暂停。确认成员状态、窗口、草稿和已发送记录，再恢复项目；必要时点击“绑定窗口”选择正确实例。

进入工作桌面期间，屏幕会切换，暂时无法同时操作原桌面。日常客户端里正在运行的工作，和共作专用实例的准备状态应分开核对。

独立桌面是同一 Windows 用户下的另一个桌面对象，能访问当前用户的本地文件。它不提供虚拟机级的隔离。客户端最小化、后台控件缺失或单实例复用等情况，可能导致自动操作失败。

### TRAE 点登录没有反应

这是当前已知未解决项。先暂停项目，检查日常桌面的官方 TRAE 是否能正常登录，以及登录是否在其他浏览器或窗口中打开。若只有独立实例失败，记录 Windows/客户端版本、启动方式和可见提示，参见 [故障排查](TROUBLESHOOTING.md)。

不要把反复点击登录当成解决办法。可暂时在项目分工中取消 TRAE，先验证已准备好的成员；这不代表三方自动会商已经通过。

## 7. 创建第一个项目

1. 点击 **新建项目**，填写名称和目标。
2. 勾选实际准备好的成员，逐个编辑分工。左侧团队只显示该项目选中的成员。
3. 第一次建议选择 **先沟通方案，再推进执行**，以便查看统筹形成的方案。
4. 在群聊发送一个小目标，例如“制作一个单文件计时器，支持开始、暂停和重置，保存到本地 HTML”。发送即进入项目流程。
5. Codex 先细化目标，分别编写成员评议提示词；收齐真实意见后，再形成具体工作单和验收要求。
6. 缺少关键条件时，在项目群聊回答问题。新目标选择“新目标 · 新开会话”；补充当前任务选择“补充本轮 · 保留上下文”。
7. 在“任务”查看分工和阶段，在“成果”查看实际本地文件或图片，在操作预览查看真实回报。

转圈、任务派发或成员声称完成，都不等于成果已经验收。没有真实回报或文件时，应按页面提示处理阻塞。

只启动软件、查看历史网页或保存设置，不会自动向成员发送目标。暂停会阻止新的共作操作；第三方客户端中已经开始的工作需到该客户端处理。

## 8. 数据保存、更新与备份

| 路径 | 内容 |
| --- | --- |
| `.data/state.json` | 项目、聊天、成员配置和任务状态 |
| `.data/projects/<项目ID>/workspace/` | 上传原文件、执行成果及报告 |
| `.data/server.log`、`.data/server-error.log` | 后台服务日志 |
| `native/bin/` | 本机生成的原生程序 |
| `artifacts/` | 手动验证结果，不是正常项目成果目录 |

更新前先暂停项目并备份 `.data/`。使用 Git 时，可以在自己有未提交修改的情况下先保存/提交修改，再拉取新版；不要用覆盖命令丢弃自己的改动。使用 ZIP 时，只更新源码，保留自己的 `.data/`，再重新构建原生组件并启动。

聊天、账户配置、登录资料和本地访问令牌不应上传 GitHub。项目的忽略规则和源码打包脚本会排除本地运行目录。

## 9. 常见问题

| 现象 | 先做什么 |
| --- | --- |
| PowerShell 禁止运行 npm.ps1 | 使用教程中的 `npm.cmd` 命令，无需修改全局执行策略 |
| 双击启动后页面打不开 | 使用终端启动，查看具体报错及服务日志 |
| 端口4318已被占用 | 确认是否已有共作实例，核对占用者，不要随意结束陌生进程 |
| 页面打开，但 AI 没工作 | 分别检查统筹连接、项目是否运行、执行成员登录/绑定和具体错误 |
| Codex 显示待命 | 待命不等于故障；需要规划时才唤起，也可显式检查连接 |
| 窗口失效或输入框无法识别 | 核对专用实例、窗口是否重启/最小化及客户端版本；重新绑定前先确认未发送或遗留草稿 |
| 额度不足 | 按官方服务提示等待重置，或自行配置备用成员；额度圆环目前是手动记录 |
| 结果不明、没有完成回执 | 先核对官方会话和本地文件，不要盲目重新发送 |

当前启动器围绕4318端口工作；高级用户虽然可以直接通过 `AGENT_DOCK_PORT` 启动 Node 服务，但相关启动脚本并未全部支持自定义端口，不建议新手仅修改一个地方就继续使用双击启动。

更多问题见 [故障排查](TROUBLESHOOTING.md)。开发者可运行 `npm.cmd test` 验证自动检查；其中使用模拟客户端，不消耗真实模型额度。真实客户端实验脚本需另行阅读并自行决定是否运行。
