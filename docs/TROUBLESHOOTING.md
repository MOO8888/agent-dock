# 故障排查

## 为什么只看见豆包？

左侧团队按当前项目分工过滤。已有项目在“项目设置 → 编辑项目分工”中选取成员；修改默认团队不覆盖已有项目。新安装默认有 Codex、TRAE、豆包和豆包工作。

工作桌面里的实际窗口是另一层状态：只有开启自动绑定/启动、路径正确、属于本项目且已进入项目运行流程的客户端才会出现。没有窗口不等于成员被删除。软件启动或只查看旧网页不会自动启动成员。

## TRAE 点击登录没有反应

该问题在实验独立桌面环境中尚未解决，目前没有足够证据确定是网络、登录回调还是客户端兼容性。

1. 暂停项目，避免后台操作干扰登录。
2. 在日常桌面自行检查同版本官方 TRAE 是否能正常登录，并观察是否打开了浏览器或其他窗口。
3. 如果仅独立桌面的专用实例失败，记录客户端版本、Windows 版本、启动参数及可见提示；不要反复创建实例或点击登录。
4. 登录、验证码和权限确认由用户完成。不要复制其他实例的认证目录、令牌或 Cookie 来绕过准备步骤。
5. 专用实例准备完成后再绑定，先核对窗口和草稿，再恢复项目。

目前可以跳过 TRAE，在项目分工中只保留已验证可用的成员继续体验；这不构成三方自动链路验收。

## Codex 显示待命或连接失败

待命表示尚未启动当前本地运行时，下次需要规划时才唤起；等待其他成员不算掉线。点击右上角状态可检查官方协议连接及 ChatGPT 登录。此操作不推理、不重发工作单，也不操作成员。

如果检查失败，按实际提示确认官方 Codex 已安装、已登录且自身可用。运行时版本和账户权限会影响可用模型；保存模型参数不等于官方已成功应用。

若上轮结果不明，请先打开该官方统筹会话核对。重连不等于重新执行，程序不会盲目重发未知结果的任务。

## 本地网页打不开

双击 start.cmd，查看 .data/server-error.log。电脑重启或服务进程结束后需重新启动。Node.js 需要在 PATH 中；原生构建需要 Windows x64 的 .NET Framework 编译器。端口4318被其他程序使用时，先确定占用者，不要随意结束陌生进程。

## 窗口已关闭、无控件或截图空白

确认绑定的是正确专用实例；客户端重启后窗口标识会变化，需要重新核对。最小化、UI更新或后台控件不支持均可能导致失败。程序会停止并提示，不能仅凭窗口标题或截图静止判断任务完成。

## 额度不足、附件未上传到官方会话

额度以各官方客户端为准；圆环目前是手动记录。等待重置或自行配置备用成员。工作台上传会保留项目本地原文件，再由统筹将文件路径交给执行者；所有官方聊天的附件按钮尚未统一适配。
