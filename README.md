# 共作 · AgentDock

> 一个海外模型会员 + 多个平台的免费额度，能不能组成一支 AI 开发团队？

## 为什么做这个项目

起点是我自己在使用 AI 开发时遇到的一个问题：一些国产 AI 工具提供了比较多的免费额度，适合承担具体执行工作；但在我的使用体验里，复杂需求理解、整体规划和多步骤推理，往往还是更依赖行业领先的模型。而这些模型更聪明，使用成本和额度也更让人舍不得消耗。

所以我想：**能不能只开一个海外模型会员，让它负责思考、拆任务、写提示词和验收，再把具体工作分给其他 AI 去做？**

共作就是围绕这个想法做的。你在项目群聊里提出目标，Codex 作为统筹者把需求变具体、编写任务提示词，再分配给 TRAE、豆包、豆包工作等成员。成员和分工可以按项目调整，执行过程与本地成果集中展示。

### 手动也能做，为什么还要做共作

其实，这套分工靠人手动协调也可以实现：让一个 AI 规划，把提示词复制给另一个 AI 执行，再把结果带回来检查。共作想做的，是把这些中间环节自动化。

**少一些人在客户端之间来回复制、传话和盯进度，多一些 AI 之间按职责进行的任务交接、问题反馈和结果核验。** 你提出目标、补充关键决定，AI 团队负责在统一的项目上下文中相互协调，让任务推进更高效。

这个想法也受到我最近看到的 Dot 群聊协作概念启发：如果不同 AI 能像群聊中的不同成员一样各司其职，把讨论、执行和检验接起来，就能减少人在中间反复协调的工作。

这也是项目希望实现的方向。目前这套自动协作流程仍在完善，不能把已经设计的流程当作全部稳定跑通的功能。

### 为什么直接调用本地客户端，而不是 API

因为对我来说，改用 API 意味着还要另外付费，这就偏离了项目最开始想解决的问题。

**共作希望直接操作各平台的官方本地客户端，使用它们提供的免费额度，或者用户本来就有的套餐额度，而不是另外购买执行模型的 API 用量。** 当前统筹也使用本机官方 Codex 的登录状态，不要求额外填写 API Key。

这个项目的目标，是让大家尽量只承担一个海外模型会员的费用，就能把多个平台现成的额度组织起来，用更低的成本完成开发。它目前还没有完整实现这个目标，实际可用额度和能力仍以各平台为准。

## 先说清楚：这还是个半成品

这个项目没有开发完。即使给 Codex 开了会员，经历了多次额度重置，我也还没有把它完整做出来。所以决定先把已有代码作为第一版开源，欢迎大家一起开发、完善。

我也不是计算机专业，主要是依靠 AI、自己的想法和不断试错，把一些原本只是设想的东西尝试做出来。代码、架构和交互里，必然还会有很多不合理的地方，欢迎直接指出，也希望大家给我建议。

后续我还会继续开发，但更新可能比较慢。我目前主要使用 Plus 会员，额度有限，同时也有自己的工作，能够投入的时间和资源都比较有限。

如果你对这个方向感兴趣，欢迎提 Issue、分享使用体验、讨论架构，或者提交 PR，一起把它补完。客户端适配、流程稳定性、测试和文档都很需要帮助。

目前已实现项目群聊、任务与成果管理、官方 Codex 统筹及部分客户端操作能力；TRAE 独立桌面登录仍有兼容问题，新版三方自动会商尚未完整验收。下面列出已实现的部分和具体使用边界。

## 已实现

- 项目群聊、可编辑成员分工、重命名、回收站和恢复。
- 新目标独立轮次，规划 → 成员评议 → 分派 → 检验 → 交付。
- Codex 官方 App Server 本地协议统筹，使用官方 ChatGPT 登录，无 API Key 回退。
- Windows 后台窗口观察、控件操作、独立桌面和人工接管入口。
- 任务依赖、验收证据、返工、未知发送结果保护和暂停恢复。
- 文件上传、本地文件交接、图片预览和成果下载。
- 可拖动工作区、角色气泡、真实操作提示和主动故障处理入口。
- 额度圆环与悬停详情：当前为手动记录，未知额度不估算。

执行成员通过官方桌面界面工作，不调用它们的模型 API。默认提供 Codex、TRAE、豆包、豆包工作四个成员；新增一个名称不等于完成了该客户端的自动适配。

## 快速开始

第一次运行？请看 **[Windows 本地部署教程](docs/DEPLOYMENT.md)**，包含环境安装、客户端准备、首次任务和常见问题。

要求：Windows x64、Node.js 22+、Windows .NET Framework 4.x 编译器。工作台无 npm 运行依赖；自动统筹另需本机可用且已登录的官方 Codex 运行时。

1. 下载并解压源码，放在自己的可写目录。
2. 安装 Node.js，重新打开终端使 node 可用。
3. 双击 start.cmd，或运行：

```powershell
npm run build:native
npm start
```

4. 打开 [本地工作台](http://127.0.0.1:4318/)。初次启动没有项目、账户或预设客户端路径。
5. 创建项目，在“项目成员与分工”中选择需要的成员。团队列表只显示当前项目选中的成员。
6. 在团队设置填写自己安装的官方客户端 .exe 路径。首次登录、验证码、文件夹信任与权限确认由用户在官方界面完成。

只浏览工作台不会调用模型或启动、绑定成员。发送目标或显式恢复项目后才开始协作。暂停阻止新的操作，已经在第三方客户端中运行的任务需要在该客户端处理。

start.cmd 将服务放到后台；关闭网页不等于停止服务。电脑重启或后台服务退出后，需要再次启动。日志和项目数据在 .data/，不进入源码包。

## 使用边界

| 能力 | 当前状态 |
| --- | --- |
| 工作台、持久化、任务和成果管理 | 已实现；自动测试覆盖 |
| 官方 Codex 自动创建统筹会话、细化目标和生成职责提示词 | 曾在本机真实验证；取决于运行时及账户可用性 |
| 豆包工作本地读写文件、图片交付 | 曾在特定客户端环境验证；不代表所有版本兼容 |
| TRAE、豆包新会话三方完整自动会商 | 尚未完整验收 |
| TRAE 在独立桌面中点击登录 | 已知可能无响应，尚未解决 |
| 通用模型选择、附件按钮、实时额度读取 | 尚未通用适配；附件采用本地原文件交接 |
| 长时间无人值守、任意智能体、多个项目并发 | 尚未验收；当前一次推进一个项目 |

AgentDock_* 是同一 Windows 用户下的独立桌面，能够访问该用户的文件；它不是虚拟机或安全沙箱。第三方 UI 更新、窗口最小化、登录弹窗和后台控件缺失均可能造成阻塞。

## 开发与验证

```powershell
npm test
```

自动检查使用隔离临时数据和模拟客户端，不需要 AI 账户或消耗模型额度。原生组件的手动检查见 [验证说明](docs/VERIFICATION.md)。不要把自动测试通过解释为所有真实客户端已适配。

```text
web/       HTML / CSS / JavaScript 工作台
src/       本地 HTTP、存储、MCP、统筹和界面投递
native/    Windows C# 后台操作及桌面控制
skills/    可选的手动统筹 Skill
tests/    Node.js 自动检查
scripts/   启动、构建、验证和源码打包
```

## 上传 GitHub

在仓库根目录运行 npm run pack:source，会生成干净的源码目录、ZIP 和校验清单。打包采用文件清单，排除 .data/、本地会话、登录配置、日志、截图、编译文件、依赖和 .git/。

上传生成的源码目录内容即可。Git 命令方式见 [发布说明](docs/PUBLISHING.md)。本项目仓库：[MOO8888/agent-dock](https://github.com/MOO8888/agent-dock)。发布自己的副本时，请使用你自己的仓库地址。
